## 새로고침 후 Firebase 데이터를 Store에 다시 반영하는 이유

store(Zustand)에 저장된 데이터는 새로고침 시 초기화된다. 새로고침 또는 재로그인했을 때 firestore DB > favorites에 저장된 찜 목록을 다시 불러와서 store에 반영해야 한다.

## DB 저장 후 Store를 갱신하는 이유

firestore DB에 데이터를 저장하더라도 화면에 데이터가 자동으로 반영되지 않는다. 그래서 store를 갱신해서 사용자가 보는 화면에도 반영해야 한다.

## 빈 메모와 찜 삭제 차이점

- 빈 메모: 찜은 존재하나, memo 속성의 값은 빈 스트링값
- 삭제: 찜 자체가 존재하지 않음 (firestore DB에 찜 데이터 X)
  찜 데이터 유무라고 볼 수도 있겠다.

## DB > UNIQUE와 FK 역할

- UNIQUE: 중복된 데이터가 존재하지 않도록 함
- FK (Foreign Key): 외래 키. 2개 이상의 서로 다른 테이블을 참조. (테이블 간 "연동"되는 개념이 아니다.)

## SQL > 전체/사용자별 집계 차이

- 전체 집계: favorites table에서 모든 사용자의 특정 데이터 조회 (빈 메모, 찜 개수 등등...) / 서비스 전체 현황 데이터를 봐야할 때 사용
- 사용자 집계: userId를 기준으로 GROUP BY로 사용자를 그루핑 -> 사용자 별로 데이터 조회 / 사용자 별로 데이터를 봐야할 때 사용

## 배열 길이로 API 개수를 계산하는 이유

favorites 배열 안에 찜이 객체로 들어있기 때문에, favorites.length를 통해 개수를 요청해서 받을 수 있다.
